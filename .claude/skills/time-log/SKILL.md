# 작업시간 기록 (임시)

목표는 **작업시간을 줄이는 것**이고, 이 시스템은 그 데이터를 모은다(#236, #239). 결과 모음과 삭제 목록은 #237.
**사용자가 지우라고 할 때까지** 따른다 - 날짜가 지났다고 스스로 지우지 않는다.

기록은 `.claude/time-log/<세션>.jsonl`에 쌓이고 커밋하지 않는다. 컨테이너가 사라지면 같이 사라지므로
**요약은 병합 요청과 함께 남긴다**(아래 3).

## 1. 자동으로 기록되는 것 (할 일 없음)

- 턴마다: 사용자 메시지부터 답을 마칠 때까지의 시간(초), 그 안의 도구 시간과 생각·답변 시간, 맥락 크기, 출력 토큰.
- 도구 호출마다: 상세 분류(깃 하위 명령, 저장소 저장, 게이트, 게임 테스트, 화면 확인, 편집, 깃허브, 세션 ...), 걸린 시간, 실패 여부.
  거부되거나 중단된 호출은 "끝나지 않은 호출"로 따로 센다.
- `python tools/check.py`: 단계마다(컴파일, 서식, 게임 테스트, 훅 테스트) 시간과 실패 여부.
- 생각·답변 나눔: 도구가 돌지 않은 시간을 바로 앞의 일(턴 시작, `<분류> 뒤`, 마지막 답변)로 묶고, 그 앞 도구가 돌려준 글자 수를 같이 적는다.
- 한 턴 안에서 일을 한 뒤 새 작업 표시를 찍으면 그 턴을 작업마다 나눈다(턴 번호 `3-1`, `3-2`).
- 작업 표시 없이(또는 병합요청 표시 뒤에) 파일을 고치면 훅이 한 번 알려 준다.

## 2. 직접 찍는 것

```
node .claude/hooks/time-log.cjs mark 작업 <유형> "#이슈 제목"   # 새 작업을 시작할 때 (첫 턴 맨 앞)
node .claude/hooks/time-log.cjs mark <단계>                       # 단계가 바뀔 때
```

- 유형: `기능`, `버그`, `자동검사수정`, `리팩터링`, `설정`, `문서`, `조사`, `기타`.
- 단계: `계획`, `조사`, `테스트작성`, `구현`, `게이트`, `화면확인`, `병합요청`, `리뷰대응`, `기타`.
- 평소처럼 일한다. 재려고 명령을 쪼개지 않는다(쪼개면 그만큼 느려져 데이터가 틀어진다). 섞인 명령은 가장 무거운 분류로 잡힌다.
- 진단용 파이썬은 `python -c`나 임시 폴더의 스크립트 파일로 돌린다(`python - <<`는 편집으로 잡힌다).

## 3. 병합 요청과 함께 남긴다 (병합 시 자동으로 같이 기록되게)

`claude/*` 병합 요청은 자동 검사가 초록이면 바로 병합되므로, **병합 요청을 여는 순간**에 기록을 붙인다:

1. `node .claude/hooks/time-log.cjs mark 병합요청` 후 `node .claude/hooks/time-log.cjs report`.
2. 병합 요청 본문 끝에 `## 작업시간 기록` 절로 이 작업의 행(작업별 표의 그 행, 턴별 표의 그 작업 행, 분류별·게이트 표)을 넣는다.
3. 같은 내용을 #237에 댓글로 남긴다(작업 이름, 유형, 이슈·병합 요청 번호, 오래 걸린 이유 한두 줄).
4. 병합 전에 고쳐 올리면(자동 검사 수정, 리뷰 대응) 올린 뒤 늘어난 턴의 표를 병합 요청 댓글로 더한다.

병합 요청 없이 끝나는 작업(조사, 질문)은 끝날 때 #237에 댓글만 남긴다. 병합을 기다리는 시간은 재지 않는다(2026-10-19 사용자 결정).
공개 저장소다 - 시각과 분류만 쓰고, 사용자 메시지 내용이나 비공개 정보는 쓰지 않는다.
