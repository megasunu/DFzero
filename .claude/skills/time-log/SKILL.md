# 작업시간 기록 (임시)

사용자가 Claude의 작업 중 무엇이 오래 걸리는지 보려고 일주일쯤 기록한다(#236, 결과와 삭제는 #237).
기록은 `.claude/time-log/<세션>.jsonl`에 쌓이고 커밋하지 않는다 - 컨테이너가 사라지므로 **작업이 끝나면 꼭 요약을 #237에 남긴다.**

## 1. 훅 자동 기록 (할 일 없음)

`.claude/settings.json`의 훅이 도구 호출마다 시각과 분류(편집, 조사, 게이트, 화면 확인, 깃, 깃허브, 명령 ...)를,
사용자 메시지와 응답 끝마다 시각을 남긴다. Claude 작업 시간과 사용자 대기 시간이 갈린다.

## 2. 단계가 바뀔 때 시각을 찍는다

```
node .claude/hooks/time-log.cjs mark <단계>
```

단계 이름은 이것만 쓴다(비교하려고): `계획`, `조사`, `테스트 작성`, `구현`, `게이트`, `화면 확인`, `PR`, `CI 수정`, `리뷰 대응`, `기타`.
작업의 첫 턴에 `계획`을 찍고, 단계가 바뀌는 순간마다 찍는다. 한 단계는 다음 mark까지이고, 사용자를 기다린 시간은 빠진다.
새 작업을 시작할 때는 작업 이름도 찍는다: `mark "작업: #N 제목"`.

## 3. 작업이 끝나면 사후 집계

PR을 연 뒤(또는 작업을 멈출 때):

1. `node .claude/hooks/time-log.cjs report`로 요약 표를 만든다(가장 최근 기록, 세션 전체).
2. 커밋 시각(`git log --format='%ci %s'`), PR이 열린 시각, CI 잡별 실행 시간(GitHub MCP `actions_list`·`actions_get`)을 더한다.
3. #237에 댓글 하나로 남긴다: 작업 이름·이슈·PR, 요약 표, 커밋·PR·CI 시각, 오래 걸린 이유 한두 줄(예: 게이트 재실행, 스모크 실패).

공개 저장소다 - 시각과 분류만 쓰고 명령 내용이나 비공개 정보는 쓰지 않는다.
